## Метод

- Драйвер `~/.hermes/plans/operit-ru/p3/drive.py` поверх adb: `uiautomator dump` → список видимых узлов (`text` + `content-desc` + `bounds`), тап по тексту, скриншот, поиск CJK в тексте экрана (`[\u3000-\u303f\u3040-\u30ff\u3400-\u4dbf\u4e00-\u9fff\uf900-\ufaff\uff00-\uffff]`).
- `walk.py` открывает список пунктов по одному, снимает `step` и возвращается назад; при ненайденном пункте останавливается, чтобы не тыкать вслепую.
- Автоматический CJK-скан дополнен просмотром скриншотов: canvas/WebView-текст и вёрстка видны только глазами.
- Язык интерфейса переключался в приложении (Настройки → Настройки языка), проход повторялся в `ru` и `en`.

## Исправления

1. `terminal/src/main/res/values-ru/strings.xml` — новый файл, 194 строки, порядок ключей как в `values/strings.xml`, zh-база байт-в-байт не тронута; терминология по `l10n/glossary.md` (Session → «сеанс», Environment → «окружение», Notice → «предупреждение», «Не удалось …», «…», «ёлочки»).
2. Ключ `l10n_settings_language_auto_native` в триаде `strings_l10n.xml` (values / values-en / values-ru: `跟随系统` / `System language` / `Системный язык`) + `LanguageSettingsScreen`: для пункта AUTO вторая строка берётся из ресурса, для остальных языков остаётся `nativeName` (названия языков по D5 не переводятся).
3. F3: `data/announcement/RemoteAnnouncementTranslations.kt` — каталог переводов, привязанный к исходному zh-тексту объявления; в `pickLocalizedContent` вставлен между поиском по языку и откатом на `defaultLocale`. Если сервер изменит формулировку, совпадения не будет и перевод не применится (никакой устаревший текст не подменяет актуальный).
4. F4: короткие ru-подписи (`nav_about` → «О программе», `nav_help` → «Справка», `tool_permission_manager`/`screen_title_app_permissions` → «Разрешения приложений», `token_activity_peak_tokens` → «Пик токенов», `token_stats_cache_rate` → «Попадания в кэш»), две строки для подписей нижней панели и заголовков карточек статистики (`DrawerContent.kt`, `TokenStatsComponents.kt`), высота пункта нижней панели 68→72 dp, а компактные даты диапазона строятся по локали (скелет `Md`: ru «30.10», en «10/30») вместо жёстких `M/d` и `MM/dd`.
5. F5: 9 ключей `l10n_memory_*` в триаде `strings_l10n.xml` (zh-значение — исходная английская строка байт-в-байт, чтобы китайский интерфейс не менялся) и замена литералов в `MemoryScreen`/`MemoryAppBar`.

## Как повторить

```bash
export JAVA_HOME=$HOME/Android/jdk21
./gradlew :app:assembleRelease
adb install -r app/build/outputs/apk/release/app-release.apk
cd ~/.hermes/plans/operit-ru/p3
python3 drive.py step <имя>      # дамп + CJK + скриншот
python3 drive.py cjk             # только CJK по текущему экрану
python3 walk.py <префикс> "Пункт 1" "Пункт 2"
```

## P4.1 — релизная сборка `ru.xvorost.operit` (2026-10-31)

Проверялось уже не debug-вариант, а релизный APK с нашей подписью: смена `applicationId` меняет
способ установки, поэтому проход по экранам повторён на чистой установке.

| Что | Фактическое значение |
|---|---|
| Сборка | `:app:assembleRelease` — `BUILD SUCCESSFUL in 3m 5s`, `GRADLE_EXIT=0` (`runs/p4_build_and_test.log`) |
| Тесты | `:app:testDebugUnitTest` — 157 наборов, 1335 тестов, 0 падений, 6 пропущено (`runs/p4_test_full.log`) |
| APK | `dist/Operit-1.12.2-ru1-arm64-v8a.apk`, 377 545 758 байт, sha256 `131045300c896d0ed6024c339817ed8fb771e21eb82173d7a00239fca51daafc` |
| Метаданные на устройстве | `versionCode=510`, `versionName=1.12.2-ru1`, подпись v2, сертификат `CN=Xvorost, OU=Operit RU, O=ru.xvorost` |

| Подпись лаунчера | в поиске приложений — «Operit» (не «Operit AI») |
| Шорткаты | длинное нажатие на иконку → «Плавающее окно голоса», «Настройки», «Восстановление данных»; тап «Настройки» открыл `ru.xvorost.operit/com.ai.assistance.operit.ui.main.MainActivity`, т.е. `targetPackage` резолвится в наш пакет |

sha256 выше относится к файлу в `dist/` — именно он ставился на устройство. Упаковка Gradle не
байт-воспроизводима: повторный `packageRelease` при неизменном коде даёт тот же размер
(377 545 758 байт) и то же содержимое, но другой sha256, потому что меняются метаданные zip. Поэтому
сверять хеш между `build/` и `dist/` бессмысленно; сверяйте содержимое (размер, `apksigner verify`,
`aapt2 dump badging`) или пересоберите `dist/` и обновите хеш.


Экраны на чистой установке (CJK-скан на каждом — 0): соглашение и политика конфиденциальности,
онбординг «Обзор возможностей 1/3…3/3», «Добро пожаловать», «Базовые разрешения», «Выбрать уровень
доступа», объявление (`Объявление` / `Понятно` с русским текстом — F3 работает и в релизе), главный
чат, меню-ящик, «Настройки ассистента», «База памяти» (F5), «Инструментарий», «Командный терминал» →
«Настройка окружения» (F1), «Настройки» → «Настройки языка» (F2: «Follow system» / «Системный язык»,
в конце списка «Russian» / «Русский»).

Английский режим: главный чат и меню-ящик — кириллицы 0, затем язык возвращён на русский.
Единственный CJK в интерфейсе — самоназвания языков `中文` / `日本語` / `한국어` (D5).

Не проверялось и в этот проход: экраны под API-ключ/аккаунт (реальный диалог с моделью, публикация в
маркет, вход в GitHub), содержимое маркета и внешних источников.

LAN-страница (`web-chat`) не проверялась, и проверять её в этом APK бессмысленно: каталога
`assets/web-chat` в нём нет (`unzip -l ~/Projects/Operit-ru/dist/Operit-1.12.2-ru1-arm64-v8a.apk |
grep -c assets/web-chat` → `0`), потому что релизная сборка шла без обязательного шага
`npm run build:webchat` (`docs/doc-src/dev-core/BUILDING.md`, п. 6). `WebChatHttpBridge` в такой
сборке отвечает 404 «Web assets are not available in app assets/web-chat». После локализации
`web-chat/src` (партия P4.C) APK нужно пересобрать с этим шагом и только затем проходить страницу на
устройстве.
